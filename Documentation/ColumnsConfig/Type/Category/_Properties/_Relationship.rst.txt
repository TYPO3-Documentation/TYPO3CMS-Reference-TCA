..  _columns-category-properties-relationship:

..  confval:: relationship
    :name: category-relationship
    :Path: $GLOBALS['TCA'][$table]['columns'][$field]['config']['relationship']
    :type: string
    :Scope: Display / Proc.
    :RenderType: all
    :default: manyToMany

    All possible values are:

    `oneToOne`
        Stores the uid of the selected category. When using this
        relationship, `maxitems=1` will automatically be added to
        the column configuration. While one record can only have a
        relation to one category, each category can
        still have a relationship to more then one record.

    `oneToMany`
        Stores the uids of selected categories in a comma-separated list.

    `manyToMany` (default):
        Uses the intermediate table `sys_category_record_mm`
        and only stores the categories count on the local side. This is the use
        case, which was previously accomplished using
        :php:`ExtensionManagementUtility::makeCategorizable()`, a static method
        removed in TYPO3 v12.

    ..  versionadded:: 13.3
        The option also decides which value a
        `Record object <https://docs.typo3.org/permalink/t3coreapi:database-record-objects>`_
        provides for this field, for example in a Fluid template. With
        `oneToOne`, it is a single
        :php-short:`\TYPO3\CMS\Core\Domain\Record` object, or :php:`null` if
        no category is selected. With `oneToMany` and `manyToMany`, it is a
        :php-short:`\TYPO3\CMS\Core\Collection\LazyRecordCollection` of
        :php-short:`\TYPO3\CMS\Core\Domain\Record` objects.

    In the following example a category tree is displayed, but only one
    category can be selected.

    ..  code-block:: php

        $GLOBALS['TCA'][$myTable]['columns']['mainCategory'] = [
            'config' => [
                'type' => 'category',
                'relationship' => 'oneToOne'
            ]
        ];

    All other relevant options, for example `maxitems=1`, are being set
    automatically.
